# 嘉立创文件转换验收报告

项目为嘉立创文件转换 JLCFConv，作者 NianBroken，项目地址为 https://github.com/NianBroken/JLCFConv。

## 实际环境与访问

验收环境为 Windows 11 x64、本机 Chrome 和应用内浏览器。设备级运行时为 Node.js v26.13.0 LTS Lithium。工具地址为 https://192.168.168.35:3443/，结果预览使用独立的 HTTPS 3444 端口。

本机使用受信任的 JLCFConv 专用根证书，浏览器测试没有跳过 TLS 校验。预览返回 COOP 和 COEP，实际检查安全上下文和跨源隔离。其他局域网设备需要信任公开根证书 `%ProgramData%\JLCFConv\tls\root-ca.cer`。

Windows 计划任务 `JLCFConv-HTTPS` 以 SYSTEM 运行，开机启动。后台监督进程在 Node 退出后重新启动服务。重启核验通过，实际状态见 `test-results/service-report.json`，当前运行信息见 `.runtime/service.json`。证书私钥不进入项目仓库。

## 实际操作流程

1. 浏览器访问生产 HTTPS 工具，使用文件选择器上传真实样本。
2. 保持默认配置，实际点击“转换并下载”，取得自动下载的独立 HTML。
3. 一次选择六份样本，实际点击转换，取得自动下载的 ZIP。
4. 解压 ZIP，核对六份 HTML 与原始文件逐一对应，文件名遵循指定前缀规则。
5. 在独立 HTTPS 预览端口打开六份结果，检查实际 PCB 画面、标题、LOGO 和目标元素。
6. 在无网络浏览器上下文直接打开六份下载文件，旋转和缩放模型，展开和收起侧栏，检查请求记录。
7. 切换文字 LOGO、SVG 图片 LOGO、自定义标题和两个独立开关，实际下载并打开对应文件。
8. 使用浏览器原生触摸输入检查按钮、左右侧栏、底栏、拖动取消、连续操作和屏幕旋转，保存实际截图。

单文件自动下载由应用内浏览器与 Chrome 分别验证。批量 ZIP、同名输入的编号子目录、部分成功和取消任务由真实浏览器与接口联合验证。测试产物保存在 `test-results`。

## 引擎与日志

资源清单共 11 项，包括当前样本版本的 WASM、字体和线程辅助脚本。每项记录来源、大小和 SHA-256，转换时使用本地校验缓存，输出内嵌资源。

HTTPS 简图核验实际检查 WebGPU。Rust 分别核验 HTTPS 共享内存多线程和离线单线程。多线程使用最多 4 个线程，与设备逻辑核心数共同确定运行预算。原引擎按 16 个线程运行时出现的 WASM 异常已经通过线程预算处理，不屏蔽控制台，也不吞掉页面异常。模式日志与请求记录见 `engine-modes-report.json`。

输出保留原厂成功运算诊断，包括布尔运算和材质默认值日志。这些诊断与页面真实错误分开记录。初始化数据首帧误报、虚构编号查询及被删除头部的坐标回调均在对应触发位置处理。

## 复测入口与兼容范围

`npm test` 执行结构和接口检查。`npm run build` 执行严格 TypeScript 检查及生产构建。`npm run format:check` 检查格式。浏览器测试脚本位于 `tests`，执行方式见 README。

最终结构与接口测试共 19 项，全部通过。生产构建、格式检查通过，完整依赖审计为 0 个漏洞。运行错误日志为空。原始文件最终摘要与计划阶段基线逐份核对通过，完整记录见 `test-results/originals-sha256.json`。

当前六份样本使用引擎 `4.1.33.9acde59c` 和界面 `1.0.353.4cd90317`。结构测试覆盖语义 class 后缀变化、模板属性、非标准 HTML、特殊字符、分段 SVG 和跨资源 CSS。未知版本缺少必要识别结构或离线资源时明确报告单文件失败，不生成假成功文件。

验收事实以对应 JSON、下载文件和截图为依据。服务由独立后台任务维持，不依赖当前对话继续运行。
