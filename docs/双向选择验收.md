# 双向点击命中与状态同步验收

验收日期：2026-11-10。项目：嘉立创文件转换 JLCFConv。作者：NianBroken。

访问入口为 https://192.168.168.35:3443/ 。生产服务使用设备级 Node.js v26.13.0 LTS，后台服务保持运行。

## 调查依据与问题原因

调查以六份真实原始 HTML、旧转换文件和当前生产转换结果为依据。六份样本的界面脚本摘要相同，引擎脚本摘要相同。原始实现使用颜色拾取，经 `modelIdMap` 转换成业务 ID，再发布 `/engine/leftClick`。

原始调查记录位于 [计划阶段调查目录](../test-results/planning-selection-current-20261110)。其中 `confirmed-baseline.jpg`、`baseline-checks.json`、`sorted-mapping-baseline.json` 和 `source-build-comparison.json` 分别保存视觉复现、基线断言、排序身份错配及源码与构建差异。

已确认并处理的原因如下。

1. 坐标显示清理规则删除了包含必要订阅的整段 React effect，旧输出无法接收模型拾取结果。
2. 仓库缺少生产构建中已经使用的选择、绘制就绪、诊断和几何模块源码，重新构建会丢失已有能力。
3. 聚合和非聚合视图共用整组扩展逻辑，非聚合操作会选中同组其他元件。
4. 位号数组和物理 ID 数组独立排序，再按位置组合，造成显示文字与模型身份错配。
5. 模型选择没有同步清除阻止目标显示的搜索，重复选择没有重新定位，空白点击没有清空两个主标识。
6. 表格延迟单击会在后续选择之后提交旧操作，画布失焦后的按键释放未清除多选状态。
7. 触摸收起面板后，兼容鼠标点击会落在下层表格，覆盖刚提交的选择。
8. 布局刷新与选择请求共用搜索清除条件，已有选中项会阻止用户主动搜索其他对象。

## 实现与行为

| 模块 | 当前职责 |
| --- | --- |
| `src/core/interactions.ts` | 按主题和调用结构保留必要订阅，接入表格控制器、搜索清除、稳定排序与选择入口 |
| `src/preview/selection.ts` | 统一选择集合、活动 ID、选择序号、高亮、物理身份和行定位，管理相关监听与观察器 |
| `src/preview/runtime.ts` | 安装公共能力，保持侧栏 Pointer Events，阻止触摸开合后的兼容点击穿透 |
| `src/core/javascript.ts` | 调用结构适配模块，坐标显示清理不删除必要交互订阅 |
| `src/core/diagnostics.ts`、`src/preview/diagnostics.ts`、`src/preview/drawing.ts` | 对接真实运行诊断与绘制就绪顺序，不覆盖 console |
| `scripts/build-server.ts` | 生成独立构建与源码映射，内嵌运行代码不引用外部映射文件 |

表格与模型统一使用原始 `UniqueID`。聚合模式选择完整 BOM 组，活动 ID 仍是实际点击的物理元件。非聚合模式只选择当前物理元件。普通点击替换选择，现有多选修饰键执行添加或取消。

选择提交同步更新 `ids`、`engineLeftClickId`、`netlistSelectedId` 和 `selectionRevision`。空白点击清空集合，将两个主标识设为 `-1`。异步高亮按版本核对，只对引擎确认存在的模型发送高亮请求。

模型点击产生待定位请求，目标被搜索隐藏时调用原组件的清除入口。用户主动搜索不属于选择请求，不清除其输入。重复点击重新保证目标行可见。侧栏收起时保留待定位目标，展开后完成定位。

排序将位号与物理 ID 放在同一记录中处理。行定位读取真实成员 ID，扣除固定表头并保留视口边距。拖动画布、操作滚动条、调整侧栏和独立勾选控件不产生额外行选择。

交互正确性始终生效，不依赖两个优化开关。原始 PCB、BOM、模型脚本和用户设备原文件不写入修改。对外接口、配置结构、下载方式和文件命名规则保持兼容。
